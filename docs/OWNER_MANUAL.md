## 2. 内部統制コンソールの3大点検指標

画面最上部バナーおよびコンソール画面において、以下の3大指標をリアルタイムで点検します。

```
┌────────────────────────────────────────────────────────────────────────┐
│ EXECUTIVE AUDIT CONSOLE [STEALTH ACTIVE]                               │
│ 諸費用差額滞留: ¥34,200  |  信販未消込債権: ¥4,800,000  |  査定相場乖離額: ¥800,000 │
│ [ 車台番号 逆引き監査 ]  [ 事実確認・照会要領 ]  [ 通常業務画面へ ]              │
└────────────────────────────────────────────────────────────────────────┘
```

1. **諸費用預り金 差額滞留残高の検証**:
   - 地方税法・自動車重量税法等の法定実費および代行手数料の合計額と、顧客預り金との差額を算定。顧客口座への全額返金（0円精算）が完了しているかを検証。
2. **信販承認済 口座未着金債権の検証**:
   - 信販会社（オートローン）の審査承認が下りている案件について、会社法人口座への実着金消込の有無を検証。
3. **下取査定額 USSオークション相場乖離の検証**:
   - USSオークション落札相場データと下取査定額を自動突合。15%以上の統計的過小査定および簿外転売疑義を抽出。

## 3. 事実確認照会プロトコル（監査照会要領）

感情論や主観的な指摘を排し、**公的証拠（税法マスタ・銀行入出金記録・USS相場）の客観的数値を基に、合理的理由と証憑原本の提示を要請**します。

### ① 諸費用預り金の差額滞留が確認された場合
> **照会要領**:  
> **「〇〇さん、対象車両（契約ID: 〇〇）の諸費用について、地方税法・自動車重量税法上の公的納付実費が〇〇円、預り金総額が〇〇円となっており、差額〇〇円の精算が未了となっています。税務コンプライアンス規程に基づき、顧客指定口座への返金振込明細書、または追加納付にかかる公的領収証書原本の提出をお願いします」**  
> 
> **【手続上の意義】**:  
> 法的根拠に基づく数値を提示することで、手元保留を防止し、顧客口座への振込返金または公的証憑の即時提出を完了させます。

### ② 信販承認済案件の口座未着金が確認された場合
> **照会要領**:  
> **「〇〇さん、対象車両（契約ID: 〇〇）のオートローン審査承認額〇〇円について、会社法人口座への着金消込が確認できておりません。信販会社発行の決定通知書原本の受領状況、および顧客からの頭金預託状況の書面報告をお願いします」**  
> 
> **【手続上の意義】**:  
> 口座消込なき納車を防止し、決定通知原本と口座入金の完全一致を確認します。

### ③ 下取査定額のUSS相場乖離が確認された場合
> **照会要領**:  
> **「〇〇さん、対象車両の下取査定額（〇〇円）と直近USSオークション基準相場（〇〇円）との間に〇〇円の統計的乖離が記録されています。査定根拠となった車両状態評価票、修復歴記録、および第三者機関査定書の提出をお願いします」**  
> 
> **【手続上の意義】**:  
> 客観相場データとの対比を明示することで、恣意的な買叩きや簿外横流しを牽制し、適正な資産評価を徹底します。

### ④ 外注加修費の高額計上（証憑未着）が確認された場合
> **照会要領**:  
> **「〇〇さん、対象車両の加修整備費用〇〇円について、提携工場の正規作業完了伝票および作業前後の現況写真が経理へ未提出となっています。インボイス制度上の損金算入要件を満たすため、納品伝票原本および写真記録の提出をお願いします」**  
> 
> **【手続上の意義】**:  
> 客観的作業記録がない支出を制度的に遮断し、架空発注や水増し請求を未然に防止します。

## 4. 業務コード体系（対照表）

システム内で使用される英字コードは、業務上の正式分類に基づき定義されています。

| コード | 画面上の呼称 | 内部統制上の定義 |
| :--- | :--- | :--- |
| **① VSS** | **Vehicle Sales Support**（車両販売管理） | 個別原価計算・三方突合照合 |
| **② FAR** | **Fee & Tax Assist**（諸費用精算管理） | 法定実費自動逆算・差額0円精算 |
| **③ LCS** | **Loan & Credit Settlement**（信販決済管理） | 信販決定通知原本受領・口座消込照合 |
| **④ PMR** | **Performance & KPI**（実績分析） | 担当者別財務指標・統計的乖離検証 |
| **⑤ TRA** | **Transaction Archive**（取引照合台帳） | 過去銀行口座記録突合・損害額特定 |

## 5. 役員・経営陣への報告用 エグゼクティブ・サマリー

経営会議または監査担当役員への報告書面案：

```text
【内部統制・財務整合性管理システム（DMS Cloud）稼働状況報告】

外車販売事業における財務統制の強化および資産保全を目的とした、
公的エビデンスに基づく自動照合システム（DMS Cloud）の導入・稼働状況をご報告いたします。

1. 現場業務と統制監査の分離運用:
現場においては、地方税法・自動車重量税法・自賠責保険料等の法定実費を自動算定する
業務効率化DXツールとして運用され、余計な摩擦を生むことなく確定成約データが蓄積されます。

2. 客観的エビデンスに基づく三方突合:
蓄積された成約データは、(1)公的税法マスタ、(2)銀行口座入出金明細、(3)USS落札相場データと
自動突合され、諸費用預り金の差額滞留、信販未消込債権、および査定相場乖離が1円単位で抽出されます。

3. 物理的出庫ロックの確立:
諸費用0円精算および信販口座着金が確認されない限り、提携行政書士への登録承認トークンが
発行されない仕組みを構築し、未清算車両の不正出庫を物理的に遮断しております。

4. 照会プロトコルの標準化:
統計的乖離が検知された案件については、感情論を排し、規程に基づく証憑原本（公的領収証、
信販決定通知書原本、車両状態評価票、写真アーカイブ）の提出を事務的に求める標準照会要領を策定済みです。

システムURL:
https://pharmacylily7077-sudo.github.io/prompt-dx/dealer.html?mode=owner
```
